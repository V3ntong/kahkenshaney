# Architecture — AmongApp

## Overview

AmongApp is a Flutter-based Lost & Found application powered by Firebase. It uses AI-assisted matching to reunite lost items with their owners. The architecture follows a clean separation of concerns with feature-based folder organization.

## High-Level Architecture

```
┌─────────────────────────────────────────────────┐
│                    UI Layer                      │
│  screens/ → pages/ → widgets/                   │
│  (Auth)    (Tabs)   (Reusable)                  │
├─────────────────────────────────────────────────┤
│                Services Layer                    │
│  auth_service.dart  otp_api.dart                │
│  chat_service.dart  kashtep_chat_service.dart   │
│  (Abstract interface + Firebase implementation)  │
├─────────────────────────────────────────────────┤
│                 Data Layer                       │
│  data/firestore/item_repository.dart            │
│  data/firestore/database_service.dart           │
│  data/storage/storage_service.dart              │
├─────────────────────────────────────────────────┤
│                Model Layer                       │
│  models/lost_found_item.dart                    │
│  models/user_profile.dart                       │
│  models/app_message.dart                        │
├─────────────────────────────────────────────────┤
│              Firebase Backend                    │
│  Auth | Firestore | Storage | Functions | FCM   │
└─────────────────────────────────────────────────┘
```

## Data Flow

### Authentication Flow
```
LoginScreen → FirebaseAuthService.login() → Firebase Auth
    ↓
DashboardScreen (auth guard checks currentUser)
    ↓
HomePage (tabs: Home, Lost, Reports, Found, Messages)
```

### OTP Flow (Signup / Reset / Change Password)
```
SignupScreen → FirebaseAuthService.register() → Firebase Auth
    ↓
OtpScreen (verifyEmail) → OtpApi.verifySignupOtp() → Cloud Function
    ↓
DashboardScreen
```

### Item Report Flow
```
ReportLostPage / SubmitFoundPage
    ↓
StorageService.uploadItemPhotos() → Firebase Storage
    ↓
ItemRepository.addItem() → Cloud Firestore (items collection)
    ↓
ItemRepository.streamItems() → ItemsGridPage grid tabs (real-time)
```

### Tab Navigation Flow
```
HomePage (PageController + TabSwitcher PageView)
    ↓  HomeBottomNav.onSelected → animateToPage
TabSwitcher._DirectionalTransition (slide + fade + scale, direction-aware)
```

## Key Design Decisions

1. **Abstract Service Interfaces** — `AuthService` and `OtpApi` are abstract classes with Firebase implementations, enabling easy testing with mocks.

2. **Graceful Firebase Degradation** — `main.dart` catches Firebase init failures and shows an error screen. `FirebaseAuthService` checks `_firebaseReady` before every call.

3. **Real-time Streams** — Item lists use Firestore `snapshots()` for live updates without manual refresh.

4. **Platform-Aware OTP** — `FirebaseOtpApi` uses Cloud Functions SDK on mobile/web and falls back to REST API on unsupported platforms (Linux, Windows).

5. **Custom Page Transitions** — Material Design 3 transitions (Fade Through, Shared Axis, Fade Slide) with `reduceMotion` accessibility support.

6. **Testable by Design** — All form widgets accept optional `repository`, `storageService`, and `onSubmit` parameters for test injection.

7. **Two Data Layers** — `ItemRepository` (typed, uses `LostFoundItem`) and `DatabaseService` (generic, returns maps, with `DatabaseException`) both cover Firestore; prefer `ItemRepository` for item features and `DatabaseService` for quick CRUD + user profiles.

8. **Direction-Aware Tab Transitions** — `TabSwitcher` animates pages with a directional slide (depends on the sign of the page offset), fade, and scale, so motion always matches the direction the user navigated.

9. **Animated Bottom Nav** — `HomeBottomNav` slides a pill indicator between tabs and animates icon scale/color/label fade via `TweenAnimationBuilder` (no `AnimationController` needed).
